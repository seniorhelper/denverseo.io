Agent-ready websites · when the visitor is software

An agent-ready website: built for the visitor that is software.

In 2026 the thing filling out your quote form may be an AI agent working for a customer. Chrome now ships a Lighthouse audit for it. We build sites that pass, and the surprising part is how much of the work is accessibility and stable layout rather than anything exotic.

An agent-ready website is one that AI agents can read, navigate and act on without a human: every interactive element has a programmatic name, the layout does not shift while the agent is working, forms are labeled and declarative, business facts are machine-readable, and, optionally, key actions are exposed as tools through WebMCP. Chrome added an “Agentic browsing” category to Lighthouse in June 2026 that audits exactly these things. DenverSEO.io builds and retrofits sites to pass it.

Google’s own AI guidance now says agents “may access your website” and describes them analyzing the rendered page and inspecting the DOM to complete tasks. Chrome’s agent-ready toolkit, published June 22, 2026, turns that into a checklist with a score. Perplexity’s Comet browser has been free to everyone since October 2025, OpenAI folded its browser work into the ChatGPT desktop app and a Chrome extension in August 2026, and Google announced Gemini agents in Chrome at I/O. The traffic is small today. The sites that are ready when it is not small will take the bookings.

This page is what the audit checks, what we change on a real site, and what we deliberately do not sell.

What Chrome’s Agentic Browsing audit checks

Lighthouse’s new category (Chrome M150) is informational, meaning it reports rather than weights a score, but its audits are concrete. In plain terms:

  1. Programmatic names on interactive elements. Every button, link, input and control needs an accessible name an agent can read from the accessibility tree. An icon-only button with no label is invisible to an agent in the same way it is to a screen reader.
  2. Layout stability. Cumulative Layout Shift is an agent problem as much as a user problem: an agent that located a button and then clicks after the page moved clicks the wrong thing. The audit reuses the CLS measurement.
  3. Declarative forms. Labels tied to inputs, meaningful names, required fields marked, errors announced. Our earlier note on agent-ready forms is the long version.
  4. Structured data. Organization, product, service and offer facts in schema.org markup, so an agent does not have to infer your hours from a paragraph.
  5. WebMCP tools (where present). WebMCP, in origin trial from Chrome 149, lets a site declare actions (“book an appointment,” “get a quote”) as callable tools with typed inputs. The audit checks whether declared tools are well-formed.
  6. llms.txt, only for errors. Chrome’s documentation calls it an “emerging convention” and the audit only fails if the file returns a server error. A 404 is not applicable. That tells you how much weight to give it.

Read that list again and notice what it is: WCAG-grade accessibility, Core Web Vitals, structured data, and one new protocol. Three of the five we have been doing for years.

What we do not sell

  • “AI agent optimization” as a separate monthly line. It is accessibility, Web Vitals and structured data. If those are in your technical SEO engagement, this is in it too.
  • WebMCP on every site. It is in origin trial and most small-business sites have one action worth exposing, if that. We add it where a booking or quote flow exists and the business can act on agent-originated requests.
  • A guarantee that agents will use your site. Nobody controls which site an agent picks. What we can guarantee is that when one arrives, it can complete the task.

FAQ

Questions, answered straight

What is an agent-ready website?

A website that AI agents (in Chrome, ChatGPT, Gemini, Perplexity’s Comet and similar) can read, navigate and act on without a human: named controls, stable layout, labeled declarative forms, machine-readable facts and, optionally, actions exposed through WebMCP.

What does Lighthouse’s Agentic Browsing audit check?

Accessible names on interactive elements, layout stability (CLS), declarative form quality, structured data, well-formed WebMCP tools where declared, and whether llms.txt returns a server error. It shipped in Chrome M150 as an informational category.

Do I need WebMCP?

Only if your site has an action an agent should complete, such as a booking or quote request, and your business can respond to agent-originated requests. It is in origin trial from Chrome 149. Most sites should fix accessibility, layout shift and forms first.

Is an agent-ready site the same as an accessible site?

Largely, yes. Agents read the same accessibility tree screen readers use, so an accessible site is most of the way there. Add stable layout, machine-readable facts and content served in the initial HTML.

How much agent traffic is there today?

Little. SE Ranking measured AI referrals at 0.32% of site traffic in early 2026 and agent-originated actions are a fraction of that. The work is cheap when done inside a normal build and expensive to retrofit under pressure later.
